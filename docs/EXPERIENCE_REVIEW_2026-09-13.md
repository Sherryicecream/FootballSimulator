# 足球生涯模拟器：第一阶段成果与体验优化评估

评估日期：2026-09-13。修订版：根据用户新增的五项体验要求更新。对象：当前工作区版本。本文是产品评估文档，不是新的实施计划；本轮仅修订本文，不修改代码、`spec.md`、路线图或活动计划。

**评估口径：用户本轮要求优先于旧规格。快速完成一段完整生涯不应超过20分钟，替代旧规格60–90分钟作为本轮快速体验标准；国内、欧洲主要联赛和日韩属于基本内容范围。** 慢读、主动展开档案可超过快速目标，但不能把强制阅读、计算或AI等待排除在快速通关计时之外。这里的“快速”指玩家的体验时长，不自动等同于新增快进按钮。旧规格尚未同步，不代表旧时长和旧范围仍是本轮验收目标。

## 1. 核心判断

**项目已完成可玩的生涯闭环，但按新增五项要求，仍有节奏、基本联赛体量、规则一致性、多周目差异和AI终章叙事五方面的实质缺口。下一阶段应同时补齐基础内容与改善体验，不能仅视为界面美化。**

最值得保留的是按月推进、不可回退的选择、确定性存档、训练与比赛的长期积累、合同承诺归因，以及退役后回看同一段经历。这些系统已能够组合出一段个人职业历程，并非只有创建页面和随机事件演示。

现在需要同时回答：完整快速生涯能否在20分钟内完成；玩家是否持续收到有意义的反馈；每个主要联赛能否独立运行；结果是否意外但有据可循；连续玩三四局是否仍有新处境；AI能否为真实经历写出个人化评价。仅增加球队名字、替换同义句或缩短按钮动画，都不足以回答这些问题。

建议首先建立“规则正确＋20分钟节奏”的可验证基线，同时把缺失联赛体量列为必要补齐项，再以三四局完整体验检验内容差异。AI用于少数关键节点和人生总结，美术为可读性、反馈和重要时刻服务。

- **实测确认**：浏览器中已经观察到的现象，不等于所有随机种子都会发生。

### 3.1 舒适性、20分钟节奏与“意外但合理”

**用户要求：** 快速完成不长于20分钟，持续收到反馈，结果出人意料、情理之中。

**重新评价：** 旧的“每月报告完整、每季若干决策”不再足以证明游戏性。以14个赛季、每季约10次月度操作作粗略预算，就已有约140次推进；若每次强制阅读与操作用时5秒，已占约12分钟，尚未算创建、选择、签约和回顾。这是负担估算，不是本次测得的通关时间。若每季仍有约10个需要仔细阅读的选择，则长生涯很可能无法舒适地落在20分钟内。

建议比较三个方向：

| 方向                                                           | 收益与限制                                                     | 评估意见                       |
| -------------------------------------------------------------- | -------------------------------------------------------------- | ------------------------------ |
| 仅优化计算速度、报告样式                                       | 减少等待，但完整阅读和点击次数基本不变                         | 必要但不足以兑现时长目标       |
| 保留月度流程，日常信息简短呈现、重点变化即时可见，详情自选展开 | 保留既有存档和月度边界，减少强制阅读；仍须真人验证长期操作总量 | 优先验证的方向                 |
| 若上述方式仍超时，再重审整段生涯的交互密度与阶段组织           | 可能实质改变游戏节奏，需要单独产品设计与回归评估               | 不在此次文档修订中直接批准实现 |

不能靠让玩家提前退役、跳过所有选择，或取消关键结果反馈来“达到20分钟”。保留现有不提供玩家侧周推进、自动整季及快进操作的约束；若将来证明确实需改变该约束，应明确提出设计取舍，不能偷偷改变。

**建议的快速路径时间预算（待试玩校准）：** 创建与开局1分钟、常规推进与简报5分钟、重要选择及即时反馈8分钟、合同/赛季转换3分钟、人生总结2分钟，共19分钟，另留1分钟余量。主线可尝试约30–40个需要认真判断的节点，并视真实阅读速度调整；这是全生涯预算建议，不是已批准的每季配额，也不要求无事件月份硬塞故事。

持续反馈应包括三层：操作立即确认已接收；结果就绪时给出具体变化与人物反应；后续月份让之前的选择产生可追踪的回响。计算中显示真实进度，不能伪造已经发生的比赛或插入人为等待。普通月份也应回答“我现在变好了还是遇到困难”，但可简短到一两句，不必每月生成长报告。

“意外但合理”需要可解释的事件链：事前有条件和征兆，发生时存在有限随机性，事后能从能力、健康、关系、球队需求和历史选择说明原因。例如高水平合同机会可以突然出现，但应来自真实球探关注或位置需求；落选可以令人失望，但不能无视长期表现和名单竞争。**公平不是次次成功，随机不是随意翻转结果。** 不向玩家公开全部概率，也不能用事后编造的文案替代真实原因。

### 3.2 联赛、球队体量与动态强弱

**用户要求：** 国内、欧洲主要联赛和日韩不能缺少；每个代表联赛及赛区应有足够的可执行球队，实力有差异且能合理变化。

**范围假设：** 本次将“欧洲主要联赛”按英格兰、西班牙、德国、意大利、法国五大联赛评估，加上中国、日本、韩国，共8个国家足球环境。这是本次范围解释，并非用户已经确认具体赛制、球队数量或真实授权内容。俱乐部继续采用原创虚构身份。

本轮从静态球队定义核对的基数：

| 当前内容池 | 球队条目                   | 当前能证明什么                               | 不能证明什么                                                             |
| ---------- | -------------------------- | -------------------------------------------- | ------------------------------------------------------------------------ |
| 国内       | 72家；层级3–8各12家        | 国内已有可观球队基数，可围绕玩家创建分层比赛 | 不能据此认定六层世界均持续运行、跨季升降级链已经完整一致                 |
| 欧洲       | 12家；层级4–8分布4/2/2/2/2 | 有欧洲职业去向与对手池                       | 没有五国独立归属与完整联赛；部分regionId仍是国内地区，不能据名称推定国别 |
| 亚洲       | 12家；日本6家、韩国6家     | 有日韩球队和海外事件                         | 职业赛季按asia组队，尚不是日本、韩国两套独立联赛                         |

**结论：这是基本内容覆盖缺口，不应继续列为可无限后置的海外扩展。**

建议先采用能完成体验目标的可运行规模：每国主联赛暂以12–20支唯一俱乐部为评估区间，下级联赛或升降级对接池建议有8–12家明确归属的球队；最终数量应跟选定赛制一起确定。这些是产品建议值，不是现实联赛当前队数，也不是已存在的内容。按每国主联赛12队计算，8个国家至少需要96个具有明确联赛归属的主联赛席位；当前静态总数恰好96家并不代表达标，因为其中72家集中在中国不同层级，海外只有24家。

“可执行球队”的验收不只数名字：球队必须有唯一身份、国家/联赛归属、初始强度和阵容、实际赛程、积分结算、合同与转会资格、跨季去向；参与升级/降级的球队应能进入合法的下一赛季。不能从其他国家临时借队填国内联赛，也不能用重复克隆队凑数。洲际赛可有跨国对阵，但应作为独立赛事解释。

各国同档球队不应自动同强，也不应用单一国籍标签刻板决定能力。建议用俱乐部资源、阵容质量与年龄、培养水平、财政空间、教练适配和声望共同形成差异：豪门强但上场竞争大，中游机会适中，小队资源少但可以给时间。强弱变化应来自跨季成长、衰退、伤病、阵容流动与资源变化，有连续性和合理幅度；不能每季完全重抽身份或为了让玩家赢而暗中削弱对手。

平衡的目标是各条路线各有代价、弱队有有限爆冷和成长机会、豪门也可能衰退，而不是让所有球队长期五五开。非玩家联赛可用较低精度结算，但应保留连续球队身份和必要的成绩、去向，不能在玩家转入时才无中生有。

### 3.3 正常运行与足球/联赛规律

**用户要求：** 游戏能正常进行，反映基本游戏规则与联赛规律。

流程可以点击到底只是第一层。F02–F05揭示的时间倒退、个人贡献违背比分、关键时刻虚构得分、全联赛统计冒充本队统计，应列为基础正确性问题。

最低评估应覆盖：

- 比分、个人进球/助攻、出场时间、赛果与积分相互一致；未出场不获得本场个人贡献。
- 同一联赛参赛身份明确，按声明的单/双循环完整生成；无意外漏赛、自我对阵、重复场次；同分排序明确，榜首不能只由球队ID决定赛季荣誉。
- 联赛与杯赛分别统计；杯赛按已声明的淘汰/平局处理规则产生下一轮，不能被淘汰后仍随意出现。
- 赛季结束后冠军、升降级、合同剩余年限、年龄和下一赛季资格一致；若有晋级名额，需要有对应的降级/补位和可运行目标联赛。
- 转会、租借、母队归属、到期返回、报名资格和伤停之间没有矛盾；国家队窗口不导致没有解释的重复比赛或出场。
- 相同种子、相同机械版本/内容和相同选择保持机械结果一致；任一中断和重载不重新投掷已完成结果。

这是虚构足球游戏的内部规则标准，不要求机械照搬现实各联赛的所有注册和财政细则。允许简化，但简化规则必须前后一致且对玩家可解释。正式选定真实赛制参考时，再核对适用赛季资料。

### 3.4 丰富文案、三四局不明显重复与种子入口

**用户要求：** 连续体验三四局不产生明显重复感，文案覆盖不同问题与情况，可增加种子输入入口。

当前有作者事件、分支与确定性变体，但不同种子只能改变抽样，不能补足缺失的事件处境、联赛内容或人物后果。欧洲和亚洲专属事件数据模块各仅有6个顶层事件定义，这说明地区专属内容仍较薄；共享池仍可能参与，不能将6个说成各地区全部可遇事件数量。

建议按“阶段×处境×人物×联赛环境”检查内容覆盖：青训争位、职业替补、巅峰、下滑；伤病与复出；合同争取与失约；留队和转会；海外适应；国家队入选与落选；退役。每个核心处境应有不同动机、选择代价、即时回应及后续走向，而不只是同一剧情的几种措辞。

三四局中的差异应至少同时体现在：开局机会与人物、主要矛盾、重要选择的后果、职业轨迹和结束评价。常规训练/比赛标签可以重复，日常足球也有重复；不能要求每局每句话都不同，也不能为避免重复而强行让相同条件产生不合理事件。

**种子入口评估建议：** 创建页提供可选输入，留空则随机；校验明确、输入后能看到并复制实际使用的种子，生涯档案保留它。它用于复现和分享世界，不能成为重抽已提交结果的入口。同种子仍须结合球员设置、内容/机械版本和选择序列才可复现；不同选择允许走出不同人生。当前隐藏种子的既有测试反映的是旧交互要求，不应阻止这次产品标准的更新。

防重复应优先依据本局已发生故事、人物和冷却，以及种子确定的内容组合。若未来引入跨生涯记忆或“避免上局内容”，必须把这些额外条件纳入可复现输入，不能在玩家输入同一种子后暗中改变世界。

建议抽取至少3组、每组4个不同种子的完整生涯，并安排真人连续玩4局。对“主要故事家族”的重复和相似处境做人工标注；核心长故事尽量在本局只走一次完整主线，重复进入应有真实新处境。可暂以跨局主要故事家族两两重合不高于约25%为内容预算预警线，排除通用系统通知，结合玩家感受再校准；它不是当前测得结果或硬性数学承诺。罕见的合理相似结局应保留，不能以保证四局必然不同结局破坏随机性。

### 3.5 AI关键点评与人生总结

**用户要求：** 在关键节点提供更丰富评价，甚至写出完整人生总结。

当前已有可选真实provider和事件反馈润色；叙事契约的kind包含event-feedback、matchday，尚无生涯总结类型，网页回顾仍采用规则评价和模板。这意味着“AI已经接入”只证明基础接入，不能宣称新的总结目标已经完成。

建议优先选择首份职业合同、重大伤病与复出、关键转会/留洋、国家队重大节点，以及退役五类场景。输入来自已提交的生涯事实，包括参与人物、具体选择、结果、职业轨迹和有证据的遗憾；输出应解释“为什么这是你的故事”，把早期选择与后来结果连起来，而不只是改写比分和添加励志形容词。

人生总结可先提供简洁结语，再展开数百字人物化回顾：起点、转折、代价、重要人物和最后留下的意义。长度应服从20分钟快速路径，长版由玩家主动阅读，不强制逐段点击。

AI不改变比赛、属性、奖励、资格或终局，不能编造冠军、出场、关系、伤病因果或错失机会。未入选国家队的球员不能因“国脚级”评价被写成已代表国家出场；场外结局也应有真实记录支持。

**时延与回退：** 先显示可靠的本地反馈与可操作按钮，AI异步补充，不阻塞推进或退役。超时、离线、输出与事实矛盾时保留作者模板；不要在玩家正在选择时突变文本或打断焦点。同一事实的已展示润色宜保持稳定；如采用缓存，不能把AI文本当作机械状态。AI关停的完整生涯仍应满足基础体量、文案和时长目标。

## 4. 基础性不足：优先处理哪些可信度问题

以下按影响划为 P1（优先解决的可信度/操作缺口）、P2（常见理解和体验阻力）、P3（深化项）。没有在本次路径观察到必现的全局流程阻断，因此不将所有问题标为最高级。

### F01 · 职业训练仍生效，但玩家失去调整入口｜P1｜实测＋实现

青训页可更改训练重点和强度。签约后的 `ProDashboard` 只有训练回执，没有训练设置，也没有接收训练调整回调。`professional-week.ts` 仍读取 `save.trainingPlan` 计算负荷、恢复和成长。

这意味着玩家可能把青训时的高强度或恢复计划带进职业阶段，之后看到疲劳或成长变化，却无法在职业仪表盘中处理。不是“尚未增加高级训练系统”，而是既有控制在阶段转换后中断。

**改善目标：** 已有训练策略在职业期仍可查看、理解和调整，尤其能够应对伤病与疲劳。

### F02 · 签约、职业赛季和回放日期不一致｜P1｜实测＋实现

本次首份合同签署日期为 **2026-09-01**，开启职业赛季后主页面日期却为 **2026-08-01**。回放里进入职业期之后的多条选择仍标为 **2025-W45**，夹在 2026 年职业比赛之间。退役页日期为 **2027-05-31**，刷新后档案显示当前日期 **2027-06-05**。

这些不是单纯格式不好看：日期倒退会让玩家怀疑比赛是否发生在签约前、后续事件是否属于当前赛季，以及存档是否恢复正确。`contract-flow.ts` 使用下一青训赛季开始日签约，`pro-flow.ts` 从签约年份的 8 月起步；回放直接使用账本的 `weekKey`，会原样暴露已有时间问题。

开发服务器还记录了 `decision-team-invite-45` 等重复列表标识警告，与职业事件继续使用青训周数构造记录ID的实现吻合。这说明时间问题也涉及事件记录身份；本次没有据此推定存档已丢失或列表实际遗漏。

**改善目标：** 所有阶段对同一个生涯时间保持一致，终局档案明确显示结束日期，历史记录与实际发生阶段对应，事件记录身份不重复。

### F03 · 职业个人数据可能违反球队比分约束｜P1｜实测＋实现

本次回放出现 **1:0 的比赛同时记录玩家 1 球、1 助攻**。无论主客方向如何，都无法解释为球员在己方一个进球中既进球又助攻。

职业比赛先生成比分，再独立抽取球员进球和助攻；`playerGoals` 和 `playerAssists` 没有收到己方进球数，也不直接接收球员位置或射门/传球能力。这既有事实一致性问题，也削弱了前锋、后卫与不同技术路线的差异。

**改善目标：** 球员贡献属于真实发生的球队进球，个人比赛数据能够与位置、表现和比分共同解释。

### F04 · 关键时刻的文案可能宣称不存在的进球｜P1｜实现

`buildMatchMomentEvent` 从已经结算的比赛账本生成事件。选项成功主要改变信心、教练评价和士气，不回改比分或个人比赛统计；但边锋文案会说“助攻队友轻松推射入网”，中场文案会说“皮球直挂死角”。

目前可以保留“已发生比赛的个人高光/表现反馈”这种边界，但界面必须如实表达。若要让玩家实际决定比赛走向，则属于之后需要独立设计的机制扩展，不能把它包装成小型美化。

另有直接呈现问题：关键时刻生成 `riskLabel: 关键抉择`，事件页只识别 low/medium/high，会回退成“未知风险”。后腰使用中场回退选项，不具有独立防守中场特色。

**改善目标：** 玩家清楚知道自己影响什么，反馈不新增比分、进球或助攻事实。

### F05 · 团队、赛事与球员的数据口径混在一起｜P1｜实测＋实现

职业总结显示“本赛季联赛已赛 **132 场**”；这是 12 支球队双循环的全联赛总数，不是本队 22 场。代码对 `proSeason.fixtures` 仅筛选 played，没有筛选本队。国内杯的“已赛 7/7”同样是赛事视角，需要明确标注。

退役总览又把包含青训的 **3 个赛季** 放在“职业生涯”下，而累计出场只显示 **21 场职业出场**。开赛零场时直接显示“联赛第 2 名”，也容易把同分排序误读成成绩。

**改善目标：** 每项数据都明确指向全联赛、本队或球员，青训与职业累计范围一致或明确拆开。

### F06 · 退役评价有维度，但标签与依据不完全一致｜P1/P2｜实测＋实现

本次只有一个职业赛季、没有荣誉、总评级为“平凡生涯”，却得到 **传奇时刻 100**、**忠诚与身份 90**。

- 传奇得分累计回放中的关键比赛次数，较高评分或普通进球比赛也进入回放，容易较早封顶；“关键比赛多”不等于“传奇”。
- 忠诚主要按俱乐部数量评分，一个赛季只效力一家便得到高分，没有充分区分短暂未转会和长期主动坚守。
- “财富与场外人生”实际来自完成故事数与海外经历，不读取职业收入，不能理解为财富评价。
- “个人表现”包含双位数进球赛季奖励，防守球员的贡献需要单独审视。
- 已结束生涯仍把无法再完成的目标显示为“进行中”，容易让人以为还能继续推进。

**改善目标：** 每个维度评价它声称评价的内容，普通人生的价值用真实经历说明，而不是靠泛化高分。

### F07 · 原始记录直接进入面向玩家的回顾｜P2｜实测

本次回顾出现 JSON 创建/周推进记录、`none → watchlist`、`training-invite`、`rotation`、`minor`、`discomfort` 和 `teammate-1` 等内部表示；“关键选择”还包含自动周推进记录。

**改善目标：** 回顾是一段可读的人生故事，有明确的人名、日期和事件意义；原始诊断数据不混入玩家正文。职业事件时间戳来源可进一步定位到 `packages/application/src/use-cases/resolve-career-event.ts`：它使用青训 `save.season` 的年份和周数构造职业阶段的选择记录。

### F08 · 存档安全已有基础，救援能力仍不足｜P2｜实现

多档案选择、失败不推进、删除确认和刷新恢复已具备，应保留。损坏档案卡片目前只有删除，没有导出诊断包；玩家也没有可见的备份/迁移出口。localStorage 本身不是应立即替换的理由，但在用户投入多段生涯后，“只能保留损坏记录或删除”仍是不完整的恢复体验。

**改善目标：** 不提供回档玩法的前提下，允许保全和导出不能读取的记录，并说明本机存储边界。

## 6. 美观与创新性

### 美观：不是没有风格，而是风格尚未贯穿完整体验

**已经做好的部分：** 深绿球场底色与荧光绿形成辨识度；场景条、图标和状态卡有共同语言；风险有文字标签，不完全依赖颜色；手机主体排列稳定。整体已有独立界面，而不是完全无样式原型。

**不足：**

1. 创建页仍像普通信息表，体育身份、环境与开局期待较弱。它与后面的球场工作台存在体验落差。
2. 大量相近圆角卡片连续堆叠，重要剧情、常规汇报与属性列表争夺相似的视觉权重。更换背景图不能解决这个问题。
3. 中文衬线观感与仪表盘用字混用、较多12–14px说明文字，使手机长阅读容易疲劳；应通过实机与字号偏好验证，不武断要求所有字体换成一种。
4. 局部控件残留默认浏览器外观。本次“查看剧情图鉴”是小型白底原生按钮，明显脱离深色主题。
5. 颜色语义不一致：创建页白字亮绿按钮、事件疲劳增加显示绿色，分别影响可读性与理解。
6. 纪录片更多表现为同类场景条与时间线，首约、首秀、失利、退役还缺少不同的情绪节奏。
7. 回顾正文出现“八个维度由存档数据直接计算”“不只靠颜色区分”等实现说明，影响玩家情绪投入。这些更适合规则说明，而非告别正文。

优先级应为：可读性与层级 → 操作位置 → 阶段识别 → 关键场景表现。先不用大量插画、复杂动画或全站重做。

### 创新：基础在“有因果的个人生涯”，不在单纯接入AI

已有价值包括：中国球员的本土起点；选择不可回退；合同承诺有因归因；故事有后续；退役回顾能追溯选择。这些比无限随机段子更能形成长期体验。

目前创新感未充分被玩家感知，主要因为：

- 阵容是每次开季重新生成，成员使用稳定形式的ID却重新抽取名字与年龄；海外也复用中文姓名加数字。竞争者难以建立可追踪的独立人生。
- 世界主要围绕当前俱乐部组装，换到海外更多改变赛事池与适应压力，还不足以呈现新增目标中的八个国家足球环境。
- 事件的文案变化不等于处境变化。真正的重玩价值应来自不同人、机会、取舍与长期后果。
- 同一类面板包装所有重大场景，玩家不容易感到“这一次与平常不同”。
- 退役评价偏向泛化分数与累计条目，尚未充分回应“我到底成为了怎样的人”。

**最适合先强化的差异化方向：** 让少数关键人物持续记住玩家的行为；让一次合同承诺、一次伤后回归、一次留队选择在后续月份中得到有据可查的回应。可先用现有事件、关系、账本与回顾表达，不必立即扩成全世界人物模拟。

这部分是相对原始产品目标的判断，没有进行外部竞品实测，不宣称市场上没有同类玩法。

## 7. 修订后的优先级：五项标准共同构成完成定义

以下是评估方向，不是代码修改清单，也不创建第二份活动实施计划。

| 次序 | 产品重点                     | 阶段成果                                                               | 判断边界                                                 |
| ---- | ---------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------- |
| 第一 | 规则可信与生涯可操作         | 解决比赛、日期、事件记录、统计口径矛盾；职业训练可持续调整             | 先保证“结果说得通”，不能用新文案掩盖错误事实             |
| 第二 | 20分钟快速完整生涯与持续反馈 | 创建到终局有明确时间预算，常规操作短、重要选择有回应，报告可快速读懂   | 不以提前退役、跳过所有选择或排除等待时间冒充达标         |
| 第三 | 必需联赛的可运行内容规模     | 国内、欧洲五大联赛（范围假设）及日韩各有明确球队、赛程、成绩和跨季通路 | 此项是基本范围补齐，与节奏设计同步规划；不是远期可选扩展 |
| 第四 | 连续三四局的差异与可复现种子 | 不同局有不同人物矛盾与轨迹，创建时可选种子，已提交结果稳定             | 不把换名字、换顺序、换同义句当作足够的新内容             |
| 第五 | 关键节点与AI人生总结         | 基于事实写出有个人特点的评价，短版即时、长版自选、失败可靠回退         | 不让AI决定机械结果，也不把基础文案不足转嫁给AI           |

视觉和可访问性贯穿以上五项：统一控件、清晰层级、手机主操作容易到达，重要节点有辨识度。它们服务舒适性和游戏节奏，不另设大规模全站改版作为先决条件。

新增要求意味着前版“暂不扩展新联赛”的判断已调整：仍不建议无边界添加新玩法，但缺少的主要联赛和内容体量必须补齐。应分批交付、逐项验收，而非一次铺开所有系统。

## 8. 新标准如何验收

以下区分用户目标与建议测量方法。**20分钟上限、基本联赛不缺席、正常规则、三四局不明显重复，是新增目标；下面的样本量、球队区间和预警阈值是评估建议，不是当前已通过的指标。**

| 维度             | 建议验证方法                                                                                                              | 通过时应能说明什么                                                                             |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 快速生涯时长     | 至少5名新玩家，含手机和非经理游戏用户；从创建到显示可读终局总结计时，包含强制阅读、选择、计算和服务等待；不要求读展开档案 | 参与快速体验者在20分钟内完成一段有实质职业历程的生涯；记录全部超时案例，不能仅报平均值掩盖长尾 |
| 阶段与终局代表性 | 除正常职业路径外，抽测青训失利、伤后回归、留洋/国家队和较长职业路径                                                       | 达标不依赖抽到短命或提前退出的生涯；失败也有内容与完整结语                                     |
| 舒适和反馈       | 记录滚动、无意义点击、请求等待、误触、求助；每次选择后让玩家解释发生了什么                                                | 玩家无需反复找推进入口，知道状态变化及代价；普通月份有简短反馈，重大事件有后续回响             |
| 意外但合理       | 抽检成功、部分成功、失败、爆冷和机会出现；对照事前状态与历史事实，请玩家复述原因                                          | 结果未必可预测，但能由真实条件解释，没有事后虚构依据或强制戏剧化                               |
| 联赛覆盖         | 按8国范围逐国列出球队及唯一归属，核查各层球队数量、正常/最少阵容、伤停、转入转出和连续多季                                | 每个代表联赛都能生成合法比赛并结算；不会借其他国家球队补国内赛程，升级和降级有落点             |
| 强弱与动态平衡   | 同版种子样本中比较豪门/中游/弱队的积分和胜率分布、强弱差档、跨季变化；观察不同职业选择的收益与代价                        | 强队整体占优但可爆冷，弱队存在合理发展路径，实力变化有原因且不强行拉平                         |
| 规则一致性       | 检查比赛贡献守恒、积分与赛果、赛程与杯赛晋级、注册/合同/伤停、时间和读档                                                  | 流程不止能跑通，关键足球事实也相互一致；覆盖本次已发现的问题                                   |
| 三四局新鲜感     | 至少3组×4个不同种子的路径抽样，另做真人连续4局；记录重复故事家族、人物关系和职业轨迹                                      | 第3/4局没有明显重复的主线体验，差异不只出现在人名和措辞；必要日常重复与主线重复分开统计        |
| 种子复现         | 相同设置、种子、内容/机械版本和选择序列重放；在事件、赛季转换、退役处读档                                                 | 机械结果一致，随机位置保存；不同种子可产生可感知差异而非保证每局必然不同结局                   |
| AI评价           | 对首约、伤病、转会、国家队和退役样本逐项核对事实，测试慢响应/离线/无效输出                                                | 总结个人化且事实无误，规则结论不被改写，AI失效不阻塞或明显拉长生涯                             |

内容规模与20分钟并不矛盾：世界可以足够大，玩家每局只需要面对与自己有关的少量重要决定。应压缩重复操作与强制阅读，保留世界运行和个人选择的深度。

## 9. 工程成熟度与验收结论应该怎样表述

现有分层、存档边界、确定性随机和大量回归测试是优点，不建议因体验问题推倒架构。另一方面，测试通过不意味着体验与足球事实全部正确：本次已经实测的日期、比赛贡献、132场口径、评价与原始字段问题，均可能在现有测试通过时继续存在。

平衡报告需要区分统计策略与自然玩家行为：

- 1,000生涯报告既包含青训指标又包含职业指标；“比赛中位22”“决策中位10”不能直接解释为整段生涯只有22场比赛或10次决定。
- 世界级比例使用退役声望阈值作为代理，不等于已验证真实竞技世界级分布。
- runner有主动在约30岁退休的策略，因此“退役年龄中位30”很大程度是测试策略，不是自然寿命模拟结论。
- `earlyRetirementRate` 统计低于30岁退休，并不直接区分是否由严重伤病导致。不能用接近0替代 spec 所要求的“重伤致极早退役”因果验收。
- 历史10,000生涯报告完成于后续声望和区域联赛调整之前，不能作为当前版本最终平衡分布的证明。当前1,000样本通过后，发布前仍需对最终规则跑同版本10,000样本。
- “独立故事组合很多”证明组合不同，不证明玩家能感知人物命运不同；后者需要体验观察。
