# 生涯开局随机化与信息展示整理设计

## 背景

当前青训垂直切面已经可以完成一个赛季，但开局和仪表盘仍暴露了较多内部实现细节：成长背景与性格由玩家手动选择，属性使用英文键名，人物关系直接展示，最近记录逐条输出底层事实并混用中英文。这些问题削弱了开局的不确定性，也让界面更像调试工具而不是生涯模拟器。

本轮调整只整理开局生成和前端信息表达，不改变月度推进、人物关系因果、比赛模拟及赛季结算规则。

## 目标

- 玩家只决定球员的基础身份，成长背景、性格倾向和初始能力由存档种子决定。
- 同一输入与同一种子生成完全相同的球员，不同种子能够产生合理差异。
- 所有面向玩家的属性名称统一使用中文。
- 人物关系继续参与后台模拟，但不在当前仪表盘中展示。
- 最近记录按月份和主题合并为简短中文摘要，避免暴露底层事件类型。

## 开局随机生成

### 玩家输入

玩家继续选择或填写：

- 姓名
- 家乡
- 主位置
- 惯用脚

成长背景和性格倾向从创建表单移除。逆足能力与其他初始能力一起由系统生成，避免玩家通过固定选择塑造过于稳定的开局。

### 生成职责

随机规则放在生涯创建的应用/模拟边界中，而不是 React 表单内：

1. 表单生成或接收一个存档种子。
2. 生涯创建用例建立带种子的随机源。
3. 同一随机源依次生成成长背景、性格倾向、逆足能力和位置相关初始属性。
4. 生成结果写入现有球员身份和属性字段，存档结构保持兼容。

成长背景从青训营、校园足球、社区足球、大器晚成中抽取；性格从雄心勃勃、沉稳、自律、张扬中抽取。首轮使用等权抽取，后续若需要结合家乡、青训入口或家庭环境调整权重，应作为独立平衡任务处理。

初始属性继续使用位置权重、地区青训设施修正和随机波动。随机化不等于无约束：中后卫仍更可能擅长防守和头球，边锋仍更可能具备速度和盘带优势。

### 可复现性

默认界面不展示随机种子，也不提供“重抽”按钮。测试和调试仍可通过应用层参数显式传入种子。同一基础输入与同一种子必须得到相同背景、性格、逆足和属性；不同种子的整体结果应存在差异。

## 中文属性展示

内部字段保持英文，以维持类型契约和模拟代码稳定。前端新增集中式展示映射，至少覆盖：

| 内部字段        | 中文名称 |
| --------------- | -------- |
| `firstTouch`    | 停球     |
| `dribbling`     | 盘带     |
| `passing`       | 传球     |
| `shooting`      | 射门     |
| `defending`     | 防守     |
| `aerialAbility` | 头球     |
| `pace`          | 速度     |
| `strength`      | 力量     |
| `stamina`       | 耐力     |
| `agility`       | 灵活     |
| `offTheBall`    | 无球跑动 |
| `vision`        | 视野     |
| `decision`      | 决策     |
| `composure`     | 镇定     |
| `determination` | 意志     |
| `discipline`    | 自律     |

球员属性卡和月报属性变化必须共用同一映射，禁止各组件自行维护中文名称。遇到未知字段时使用明确的中文兜底文本并在开发环境暴露问题，不把英文键名展示给玩家。

## 人物关系展示边界

从当前仪表盘移除“关键人物”卡片及信任、尊重、亲近等数值。`relationships` 数据及相关模拟逻辑全部保留，因为教练、队友和其他人物仍会影响事件触发与生涯走向。

本轮不设计新的关系界面。未来如果加入人物页，应使用叙事化状态（例如“教练开始信任你”），而不是直接展示底层数值。

## 最近记录聚合

### 展示模型

前端通过纯展示函数把事实账本投影为“月度摘要”，不修改原始账本。默认展示最近三个月，每月按照以下主题最多生成一条摘要：

- 比赛：出场数、进球、助攻或具有代表性的比赛结果。
- 成长：训练成果与主要属性变化。
- 健康：受伤、恢复或显著疲劳变化。
- 机会：教练评价、一线队观察、跟训、名单或出场进展。
- 场外：真正影响生涯的选择或人物事件。

没有重要变化的主题不输出。摘要使用自然中文，不显示 `MATCH_PLAYED` 等内部类型，不逐条复述所有事实，也不展示内部标识符。

### 信息密度

每个月显示一个可扫描的记录块，标题为年月，正文优先整合为一至三句。比赛与成长属于常规信息；伤病、一线队机会和关键选择具有更高优先级。若一个月事实很多，保留总量和关键结果，省略重复训练或常规状态更新。

月报与最近记录职责不同：月报强调刚刚推进月份的量化变化，最近记录负责回顾近三个月的生涯脉络。二者都使用中文展示映射，但不重复整段底层事实。

## 错误处理与兼容性

- 旧存档已有的背景、性格和逆足数据继续照常读取。
- 新随机规则只作用于新建生涯，不迁移或重抽旧存档。
- 空账本或不足三个月时正常展示已有月份；完全没有记录时显示简短空状态。
- 未识别的事实类型不直接展示英文，可忽略或归入“其他进展”的中文摘要。

## 测试策略

采用测试驱动方式覆盖以下行为：

1. 同一种子生成相同的背景、性格、逆足和初始属性。
2. 多个不同种子能够产生不同的开局组合。
3. 创建表单不再出现背景、性格、逆足和随机种子控件。
4. 属性卡和月报只显示中文属性名称。
5. 仪表盘不渲染人物关系卡及关系数值。
6. 最近记录按月份聚合、只显示中文摘要、限制为最近三个月。
7. 空记录和未知事实类型具有安全的中文展示结果。
8. 完整桌面端和移动端赛季流程继续通过。

## 非目标

- 不调整赛季比赛数量和月度推进节奏。
- 不重新平衡成长曲线、伤病概率和一线队晋升概率。
- 不删除人物关系、事实账本或内部英文契约字段。
- 不在本轮加入人物详情页、完整生涯日志页或手动重抽功能。
