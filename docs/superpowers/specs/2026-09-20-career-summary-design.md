# 生涯总结与可选 AI 增强设计

## 目标

退役后的生涯回顾必须在没有网络、没有 API 或 API 失败时仍然提供完整的总结与评价。可选 AI 只负责改善语言组织和概括，不参与事实计算，不改变比赛、属性、荣誉、人物关系、伤病因果或存档内容。

## 事实来源

生涯总结的事实包由本地已结算数据生成，来源包括：

- 球员身份：姓名、出生地、位置、国籍；
- 生涯概况：赛季数、效力俱乐部数、出场、分钟、进球、助攻、国家队出场与进球；
- 按赛季职业轨迹：俱乐部、出场、进球、助攻、评分和赛季结果；
- 可追溯的重要节点：选择、反馈、合同、比赛、国家队和伤病事实及证据 ID；
- 已结算荣誉、八维评价和幕后档案；
- 生涯结局和退役日期。

历史档案直接使用其中预先计算的 review 与履历，不能通过 AI 重新推导缺失历史。旧档案缺少字段时显示已有事实，不猜测日期、荣誉或经历。

## 本地总结

本地总结是必需能力，由确定性模板和事实映射生成：

- 短版：150–250 字，退役页加载后立即显示，至少包含球员姓名和一个真实关键转折点；
- 长版：400–800 字，默认折叠，玩家主动展开时显示；
- 评价使用现有生涯结局、八维评分、荣誉和幕后档案，不生成未在事实包中的内容；
- 没有国家队经历时必须明确为 0 场或未入选，不能用评价等级推断国家队经历；
- 没有荣誉、关系、伤病或错失机会时显示对应的本地空状态。

## AI 增强

AI 是可选的表达增强层，采用现有本地叙事客户端和安全回退链：

- 请求继续使用 `POST /v1/narrative-polish`，通过 `kind: 'career-summary'` 区分生涯总结；
- 使用 `mode: 'short' | 'long'` 区分短版和长版；
- AI 输入只包含结构化事实包、允许引用的证据和目标字数，不发送完整可变存档；
- 输出只包含总结文本，不返回任何机械字段；
- 服务端沿用 schema 校验、事实数字围栏、超时、缓存和 provider fallback；
- 相同规范化事实包与模式使用同一个 SHA-256 cache key，不重复请求；
- API 未配置、网络失败、超时、无效输出或离线时，页面继续显示本地总结，不显示错误横幅；
- AI 文本不写入玩家存档，刷新后可重新从本地事实生成。

首批 AI 节点：

1. 退役页的短版总结作为异步增强；
2. 玩家点击“展开 AI 人生总结”后请求长版；
3. 既有关键事件反馈润色继续使用原有 `event-feedback` 流程。

## 页面行为

退役页在八维评价和幕后档案附近增加“人生总结”区块：

- 先显示“本地生涯总结”；
- AI 短版返回后在同一区块显示为“AI 叙事增强”，不覆盖本地事实评价；
- 长版默认折叠，按钮触发请求；
- 请求期间显示轻量加载状态，不阻塞回顾页其他内容；
- 失败、超时或无 API 时保留本地长版；
- 历史存档与正在结束的生涯使用同一展示逻辑。

## 代码边界

- `packages/contracts`：定义事实输入、短/长输出、模式、版本和 `career-summary` kind；
- `packages/application`：从已结算回顾与履历构造事实包和版本化 prompt；
- `apps/web`：异步请求、缓存状态、回顾页展示和本地 fallback；
- `apps/local-ai`：复用安全适配器和 HTTP 服务，扩展 career-summary schema 与验证；
- 不修改 simulation 的比赛、属性、荣誉和退役结算规则；
- 不将 AI 输出写入 `CareerSave` 或 `CareerArchiveV1`。

## 验收

- schema 能阻止把不存在的荣誉或国家队经历放入事实包；
- 本地短版和长版在无 API 时也能稳定生成并满足字数范围；
- AI 成功时本地总结与 AI 总结同时可见；
- AI 失败时页面内容完整，且不出现失败横幅；
- 同一事实与模式只触发一次请求；
- 事件反馈原有 AI 润色回归不受影响；
- 不改变存档内容和既有模拟结果。
