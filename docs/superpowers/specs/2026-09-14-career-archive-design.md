# Task05：生涯存档生命周期与历史回顾设计

## 1. 背景与目标

项目已经支持生涯自动保存，但当前进行中的存档和已经结束的生涯仍以同一类完整运行态数据处理。Task05 在保留现有存档安全策略的基础上，补齐以下能力：

- 进行中的生涯尽可能原样保存，并能从原位置继续；
- 生涯结束后，将存档转换为只读历史档案，保留回顾所需的完整信息；
- 在存档页面区分进行中的生涯、历史生涯和损坏档案；
- 历史生涯可以阅读、导出或手动删除，不自动清理；
- 原始存档导出不解析、不重写、不删除，避免损坏档案失去恢复证据。

本设计不改变 v3 月度推进流程、不向 UI 引入模拟规则，也不允许历史档案重新模拟或重新随机。

## 2. 已确认的产品决策

采用“同槽位生命周期转换”方案：

1. 进行中的存档继续使用原有槽位和完整 `CareerSaveV7`。
2. 生涯结束后，原槽位转为只读历史档案。
3. 历史档案保留在原槽位，只有玩家主动删除才会释放槽位。
4. 创建新生涯不会自动覆盖活动存档或历史档案。
5. 历史档案不能恢复为可继续推进的生涯，也不提供导入恢复流程。

备选方案是增加独立历史槽位，或始终保存完整终结存档；前者会增加槽位同步和迁移复杂度，后者无法满足结束档案的精简要求，因此不采用。

## 3. 存档模型与生命周期

存档外层增加明确的生命周期类型：

```text
active   完整的进行中存档，可继续游戏
archive  已结束的只读历史档案，可查看回顾
invalid  无法解析、校验失败或迁移失败的内容
```

建议的外层结构为：

```text
{
  storageVersion: 2,
  kind: "active" | "archive",
  savedAt: ISO 日期字符串,
  data: CareerSaveV7 | CareerArchiveV1
}
```

`CareerArchiveV1` 是稳定的展示数据快照，不包含继续模拟所需的运行态。它至少包含：

- 球员身份、最终年龄、位置、最终声望和最终状态；
- 生涯结束日期、结束原因、结局评价和生涯等级；
- 预计算的人物评价、能力维度、幕后表现和关键经历；
- 赛季履历、俱乐部履历、转会相关记录、贷款和海外经历；
- 国家队履历；
- 出场、进球、助攻、分钟数等总计与赛季统计；
- 荣誉、奖杯和其他可展示的荣誉象征；
- 现有回顾页面所需的时间线和关键事件回放。

以下数据不进入历史档案：

- 未完成赛季的完整赛程和比赛运行态；
- 随机数状态、随机位置和事件游标；
- 待处理事件、训练负荷、疲劳、冷却和暂停状态；
- 继续推进当前生涯所需的其他内部状态。

历史档案中的回顾数据由 application 层在生涯结束时从完整存档生成，并在读取时按 `CareerArchiveV1` 校验。阅读档案只展示快照，不调用模拟器，不重新生成评价。

## 4. 归档与保存流程

### 4.1 进行中存档

应用层保留现有的完整保存流程。保存操作必须先完成序列化和校验，再替换槽位内容；任何写入失败都不得先删除旧内容。

保存失败时必须满足：

- 页面中的当前存档、随机位置和待提交状态保持不变；
- 槽位中的旧原始内容保持不变；
- UI 显示可区分的失败原因并提供重试；
- 多个生涯槽位互不影响。

### 4.2 生涯结束归档

1. 先得到完整的终结 `CareerSaveV7`。
2. application 层生成 `CareerArchiveV1`，包括回顾页所需的评价、经历、统计和荣誉。
3. 归档数据通过契约校验后写入原槽位。
4. 新档案写入成功后，原槽位才视为历史档案。
5. 归档或写入失败时保留原完整终结存档，不删除、不覆盖，并向用户提示“历史档案转换失败”。

当前会话可以直接使用内存中的终结数据打开回顾页面；刷新或重新进入时读取持久化的历史档案。

对于历史版本中已经存在的完整终结存档，读取时提供兼容转换：先在内存中生成历史档案，转换写入失败时仍保留原内容并允许查看；只有转换成功后才替换原槽位，避免迁移失败造成数据丢失。

## 5. 分层职责

### contracts

- 定义 `CareerArchiveV1` 及其 schema；
- 定义 active/archive/invalid 存档读取结果；
- 为持久化端口定义原始导出和归档写入所需的接口。

### simulation / application

- 由现有生涯回顾构建逻辑生成稳定的历史展示数据；
- 负责把完整终结存档转换为 `CareerArchiveV1`；
- 负责归档时机、兼容旧终结存档和失败后的状态保持；
- 不把浏览器存储规则或下载实现放入模拟器。

### web / persistence

- localStorage 适配器负责原始内容读取、版本校验、写入和导出；
- 浏览器端负责把原始内容或正常档案包装为下载文件；
- UI 只负责展示档案状态、触发继续/查看/删除/导出，不复制模拟规则。

## 6. 存档列表与回顾页面

存档选择页保留现有页面入口，并增加清晰的生命周期分区。

进行中的生涯卡片显示：

- 球员、当前年龄、地点和当前日期；
- 当前阶段和最近保存时间；
- “继续”操作；
- 删除操作。

历史生涯卡片显示：

- 球员和结束日期；
- 最终评价或生涯等级；
- 效力球队、赛季数量和主要统计；
- 荣誉数量或代表性荣誉；
- “查看回顾”“导出备份”“删除”操作。

损坏档案卡片显示可理解的损坏原因，并提供“导出原始档案”和“删除档案”。原始导出必须直接返回存储中的原始字符串，不能因为 JSON 损坏而失败，也不能在导出过程中修改槽位。

`CareerReviewPage` 扩展为同时支持完整终结存档和 `CareerArchiveV1`。历史模式下继续展示：结局、人物评价、能力维度、赛季时间线、俱乐部/转会经历、国家队履历、数据统计、荣誉和关键事件回放，但不显示继续推进或改变状态的操作。

## 7. 错误分类与用户反馈

错误提示至少区分：

- 读取失败；
- JSON 解析失败；
- 存储空间不足；
- 浏览器拒绝本地存储或权限异常；
- 存档版本迁移失败；
- 历史档案转换或压缩失败。

“导出原始档案”是故障恢复证据，不是恢复流程。项目本阶段不实现导入恢复，避免未经验证的外部内容进入模拟状态。

## 8. 测试设计

在实现前先为关键行为编写失败回归测试，至少覆盖：

- 损坏 JSON 的原始导出；
- 原始导出不删除、不重写存档；
- 保存失败时旧内容、页面状态、随机位置和待提交状态保持不变；
- 归档成功后刷新仍可查看历史回顾；
- 归档失败时完整终结存档仍可读取；
- 旧版完整终结存档的兼容转换；
- 活动、历史和损坏档案在列表中正确分组；
- 历史档案不能继续推进；
- 历史档案只可手动删除，不发生自动清理；
- 两个生涯槽位互不污染；
- 回顾页面能完整展示人物评价、经历、转会、履历、统计和荣誉。

随后运行 Task05 的单元测试、存档安全端到端测试，并执行项目规定的 G1 全量验证。

## 9. 非目标

- 不增加每周推进或快进入口；
- 不改变比赛、训练、杯赛或荣誉平衡规则；
- 不把存档压缩逻辑放进 simulation；
- 不实现外部文件导入和档案恢复；
- 不自动删除旧历史档案；
- 不在历史回顾时重新运行模拟或重新抽取随机结果。
