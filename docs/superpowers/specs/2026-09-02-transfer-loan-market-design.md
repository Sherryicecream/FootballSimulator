# 转会与租借市场设计

> 状态：已获用户批准
>
> 日期：2026-09-02
>
> 前置：M10 职业期赛事深度已完成；现有职业休赛期和自由球员流程保持兼容。

## 1. 目标

把职业生涯中的俱乐部流动从“合同到期后自由转会”扩展为每个赛季都可参与的职业市场。玩家在赛季结束后能够基于出场机会、层级、薪资和发展空间，选择留队、永久转会或租借；结果必须影响下一赛季的球队、履历、荣誉和可见叙事。

本模块首先服务于三个用户感受：

- 每个赛季末都有明确的职业选择，而不是只能被动接受续约。
- 租借是有真实约束的职业路径：合同仍属于母队，球员代表租借俱乐部比赛，赛季结束自动回归。
- 报价不是随机装饰，而是由能力、位置需求、层级上限、年龄、声望和适应力共同决定。

## 2. 范围

### 2.1 包含

- 职业休赛期的留队、永久转会和租借入口。
- 国内及海外俱乐部的确定性市场报价。
- 永久转会签约、旧俱乐部履历收口和新赛季接续。
- 一年期租借、母队合同保留、租借俱乐部参赛、赛季末自动回归。
- 租借履历、租借赛季数据和市场结果进入赛季总结与生涯回顾。
- 旧自由球员市场继续可用；自由球员仍可等待下一转会窗口。
- 新增的市场、租借和回归账本事实。
- 单元测试、存档迁移测试、浏览器流程和长期平衡指标。

### 2.2 不包含

- 转会费谈判、竞价、经纪人佣金或复杂的俱乐部许可谈判。
- 半赛季租借、买断条款、租借转换永久转会。
- 多名球员的完整世界转会数据库。
- 训练系统重做；训练可视化仍留在后续模块。

## 3. 玩家流程

职业赛季结算后进入 pro-offseason：

1. 若合同仍有效，显示当前俱乐部的留队入口，并允许打开职业市场。
2. 若合同到期且存在续约报价，玩家可接受续约留队，或进入职业市场。
3. 玩家选择永久转会或租借后，系统生成本窗口报价。
4. 玩家可签下一份报价，或放弃本窗口并按当前合同留队；自由球员继续使用现有等待窗口。
5. 永久转会签约后进入 professional-contract，再由现有入口开启下一职业赛季。
6. 租借签约后进入 professional-contract；下一赛季由租借俱乐部开赛，合同归属仍是母队。
7. 租借赛季结算时先记录租借履历和目标俱乐部赛季结果，再自动回到母队，随后进入下一次休赛期选择。

签约前只需要一次确认。永久转会不可逆；租借不是永久转会，但会锁定下一赛季的参赛俱乐部。

## 4. 市场报价模型

市场报价由 simulation 生成，application 只负责阶段校验、保存和流程编排。

报价候选使用现有兴趣评分和能力层级天花板，并额外加入：

- 球员当前能力与潜力：影响目标层级和角色。
- 主要位置与俱乐部位置需求：影响兴趣和预计出场机会。
- 年龄、声望、当前表现和合同承诺：影响报价质量。
- 永久转会与租借使用同一层级上限；租借不允许绕过能力天花板。
- 海外俱乐部仍要求 adaptability 达到 55；海外薪资和声望规则沿用现有模型。
- 同一窗口不生成重复俱乐部报价；候选不足时可以少于四份，但不会伪造保底报价。
- 生涯种子、当前赛季、市场类型和自由球员窗口序号共同决定随机游标，保证同输入同输出。

报价分为 permanent 和 loan 两种。永久报价复用现有合同年限、薪资、角色和承诺字段；租借报价也展示目标俱乐部、层级、预计角色和发展承诺，但租借期限固定为一个赛季。

## 5. 存档与领域状态

保持 CareerSaveV5 版本，新增 activeLoan 与 loanHistory 字段都提供兼容默认值，不改变现有职业阶段机。

### 5.1 报价

ContractOfferV3 增加 offerKind，取值为 permanent 或 loan，默认 permanent。旧存档和旧内容没有该字段时按永久转会解析。

租借报价的 clubId 表示租借目标俱乐部；当前 SignedContract 不被租借报价替换，避免把母队合同错误地当成目标队合同。

### 5.2 当前租借

新增 activeLoan，空值表示没有正在进行的租借；非空时保存：

- parentClubId、parentClubName、parentClubTier：母队和合同归属。
- loanClubId、loanClubName、loanClubTier：当前赛季代表的目标俱乐部。
- startedOn、returnsOn：租借开始和自动回归日期。
- seasonId：绑定唯一职业赛季，防止跨赛季重复结算。

proSeason 的当前参赛俱乐部由 activeLoan.loanClubId 优先决定；没有租借时继续使用合同俱乐部。contract.clubId 始终保留母队合同归属。

### 5.3 租借履历

新增 loanHistory 数组，记录已完成的租借经历：

- seasonId、parentClubId、parentClubName。
- loanClubId、loanClubName、from、to。
- appearances、goals、assists、minutes。
- competitionTier 和 outcomeEvidenceId。

clubHistory 继续记录永久俱乐部履历，loanHistory 单独记录租借履历，避免出现两个无法区分的“当前俱乐部”记录。生涯回顾合并两者时按日期排序并标记“租借”。

### 5.4 层级和荣誉

永久转会赛季沿用现有 nextClubTier 继承规则。租借赛季的升级/降级和荣誉归属于租借目标俱乐部，但不会改变母队合同层级；租借结束时 activeLoan 清空，母队合同 tier 继续作为下一赛季基础。

租借目标俱乐部获得的杯赛或联赛荣誉仍写入该赛季历史，并标记为球员在租借期间获得。母队不会错误继承租借目标俱乐部的升降级。

## 6. Application 用例

新增或调整以下 application 边界：

- requestCareerMarket：只允许 pro-offseason，记录 market-window 账本事实并生成所选类型的报价。
- signMarketOffer：校验报价属于当前窗口；permanent 在职业休赛期关闭现有履历并替换合同，free-agent 继续复用 signTransfer 兼容语义；loan 建立 activeLoan，不替换母队合同。
- returnFromLoan：只允许租借赛季完成后的内部阶段转移；写入 loanHistory 后清空 activeLoan。
- generateFreeAgentOffers 和 signTransfer 保留原签名，作为自由球员兼容入口。
- completeProfessionalSeason 在结算顺序中先使用当前参赛俱乐部统计，再根据 activeLoan 决定记录租借履历和清理状态。
- web 不直接改变 careerPhase、activeLoan、clubHistory 或 nextClubTier。

非法阶段、重复签约、过期报价、目标俱乐部不存在、海外适应力不足和重复租借都返回明确错误，不改变存档。

## 7. Web 交互

ProOffseasonPanel 增加职业市场区域：

- 当前俱乐部卡：合同归属、剩余年限、当前层级和留队后果。
- 市场入口：永久转会和租借两个清晰按钮。
- 报价卡：俱乐部徽记/语义图标、层级、角色、预计出场、薪资、合同归属和回归日期。
- 租借报价必须明确显示“合同仍归母队”“本赛季代表目标俱乐部”“赛季末自动回归”。
- 签约确认只出现一次；等待或没有报价时展示市场冷淡原因和下一窗口提示。
- 赛季总结与生涯回顾显示租借俱乐部、租借赛季数据和租借期间获得的荣誉。

所有规则和结果来自 application/simulation；前端只显示状态和调用回调。移动端保持单列布局，无新增横向滚动。

## 8. 确定性、错误处理与兼容

- 相同存档、内容包、市场类型和种子必须生成完全相同的报价及签约结果。
- 旧 v4/v5 存档没有 activeLoan、loanHistory 或 offerKind 时安全解析为空值/永久报价。
- 读档时若 activeLoan 的 seasonId 与当前 proSeason 不一致，迁移层直接拒绝该存档；不静默清理，也不允许代表错误俱乐部参赛。
- 市场无报价不是异常；玩家可保持当前合同或在自由球员状态等待下一窗口。
- 租借回归是幂等的；重复刷新、重复提交和重复赛季结算不能生成第二条履历或重复统计。

## 9. 测试与平衡

必须先添加失败回归测试，再实现行为：

- ContractOfferV3 旧数据默认 permanent；activeLoan 和 loanHistory 能迁移并通过 schema。
- 同种子、同市场类型、同存档生成相同报价；不同能力和适应力产生可解释差异。
- pro-offseason 可以分别打开永久转会和租借市场；非法阶段和过期报价被拒绝。
- 签永久转会会关闭旧履历；签租借不会关闭母队合同。
- 租借赛季的联赛、杯赛、月报、球员统计和球队层级使用目标俱乐部。
- 租借赛季结束只回归一次，数据与荣誉进入 loanHistory/seasonHistory，母队层级不被目标队升降级污染。
- 赛季总结、生涯回顾和移动端页面显示租借标记。
- 浏览器 E2E 实际完成一次“休赛期 → 租借报价 → 租借赛季 → 自动回归”。
- 平衡报告新增 permanentTransferRate、loanRate、loanReturnRate、loanSeasonAppearanceRate 和 overseasMoveRate；长期运行不得降低完成率或破坏原有生涯分布。

## 10. 完成定义

1. 玩家每个职业赛季末都能看到留队、永久转会和租借的明确选择。
2. 永久转会改变下一赛季俱乐部，租借保留母队合同并在赛季末自动回归。
3. 球员比赛数据、球队成绩、荣誉和生涯回顾能区分永久效力与租借经历。
4. 旧自由球员流程、月度职业赛季、杯赛、升级/降级和存档读取保持兼容。
5. 核心测试、类型、Lint、格式、构建、E2E 和 1,000 生涯平衡门禁完成。

### 平衡校准补充

平衡模拟必须同时覆盖永久转会和租借两条职业路径。验证策略使用固定种子选择市场路径，不改变玩家端规则；租借率与永久转会率分别以实际请求对应市场的生涯为分母，租借回归率以发生租借的生涯为分母，租借出场率以完成租借赛季的生涯为分母。
新增市场合同允许“无出场承诺”路径，因此职业承诺兑现率上沿从旧职业期口径的 95% 调整为 99%，仍保持 70% 的下沿；生涯平均转会次数继续保持在 0.5–2.5，留洋占比保持在 10%–30%。
