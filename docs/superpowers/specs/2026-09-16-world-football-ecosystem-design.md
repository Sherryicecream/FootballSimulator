# 世界足球生态设计

**日期：** 2026-09-16  
**状态：** Task12A–12E 已实现并完成全量验收；国家队完整赛事安排仍留待后续任务
**关联任务：** Task11（240 队俱乐部内容）、Task12（八国独立赛程、日历与升降级）、Task12A–12E（世界生态覆盖、洲际、转会与动态）

## 1. 目标

Task11 已将项目的俱乐部内容扩充至 240 队，但“有数据”不等于“有参与机会”。本设计将 240 队接入一个可持续运行的世界足球生态，使俱乐部能够在不同层次参与：

- 每年参加本国所属级别的联赛；
- 通过联赛、杯赛和资格赛获得洲际赛事机会；
- 作为世界转会市场中的转入方、转出方和观察方；
- 因升级、降级、荣誉、转会和洲际资格出现在传闻与新闻中；
- 在较长时间窗口内保持合理的球队覆盖和动态轮换。

目标不是让 240 队每年平均出现，而是让每支球队都拥有符合竞技成绩的参与路径，同时避免同一批球队长期垄断玩家看到的内容。

## 2. 设计原则

### 2.1 国内赛事全覆盖，洲际赛事按成绩竞争

国内联赛是所有俱乐部的基础参与层。240 队按国家和级别进入独立赛历，每支球队在所属联赛中拥有完整赛季和可追踪的赛季摘要。

洲际赛事不向所有球队发放随机名额。资格应由国内排名、国内杯赛、俱乐部实力和最近洲际表现决定；轮换只在实力相近的候选者之间生效，不强行排除持续夺冠的强队。

### 2.2 反重复是软约束，不是强制平均

近期已经参加过洲际赛事、连续出现在新闻或频繁进入玩家市场的俱乐部，应在实力接近时获得轻微扣分。真正的冠军、杯赛冠军或强势崛起球队可以突破冷却，保持足球世界的连续性和因果性。

### 2.3 世界模拟与玩家视野分离

后台可以让 240 队全部参与计算，但玩家界面只展示与当前俱乐部、联赛、国家队、洲际对手或职业目标相关的少量内容。玩家市场的 3 家海外代表队仍然是可读性控制，不代表整个世界转会市场只有这些球队。

### 2.4 每条动态必须有事实来源

新闻和传闻只能由已发生的赛季、杯赛、洲际、转会或球队状态事实生成。动态记录必须能追溯到 `relatedFactId`，不能为了覆盖率凭空编造球队故事。

### 2.5 保持确定性和存档可恢复

所有背景赛果、资格选择、转会候选和传闻排序都使用显式种子随机源。活动存档保存足以恢复世界状态的摘要；结束存档只保留与玩家相关的历史信息和最终回顾所需数据。

## 3. 参与模型

### 3.1 国内联赛层：240 队每年都有比赛

Task12 提供八国独立日历和升降级链后，每支俱乐部通过 `country` 和 `tier` 找到唯一的本国联赛：

- 中国 6 个级别，每级 12 队；
- 英格兰、西班牙、德国、意大利、法国、日本、韩国各 2 个级别，每级 12 队；
- 同级 12 队进行双循环，每队 22 场；
- 赛季末所有非玩家联赛只保存排名、积分、进失球、杯赛和升降级摘要；
- 玩家所在联赛继续保存详细赛程、比赛事件、个人统计和承诺分母。

因此，国内赛事覆盖率的硬指标是每个赛季 240/240 家俱乐部都有所属联赛赛季摘要。

### 3.2 洲际赛事层：资格、轮换和可见度

按现实洲际归属分为：

- 欧洲：英格兰、西班牙、德国、意大利、法国；
- 亚洲：中国、日本、韩国。

每个赛季的洲际候选池由以下球队组成：

1. 各国顶级联赛冠军和前若干名；
2. 各国国内杯赛冠军；
3. 上一赛季洲际赛事的保级/晋级球队；
4. 少量资格赛名额；
5. 因升级、杯赛爆冷或持续表现而进入候选池的中小俱乐部。

候选排序使用可解释的综合分：

```text
洲际资格分 = 国内排名分
           + 国内杯赛分
           + 俱乐部实力分
           + 近三年洲际表现分
           - 近期连续参赛扣分
```

最终实现时，名额数量应放在内容/赛事配置中，而不是散落在 UI 或推进逻辑中。第一版可采用“直接晋级 + 资格赛”的两级结构；非玩家球队只模拟结果摘要，玩家球队才展开洲际逐场详情。

为避免固定豪门垄断，候选排序增加以下规则：

- 同一俱乐部连续参赛时累计轻微扣分；
- 最近 3 个赛季的洲际出场次数纳入扣分；
- 实力分差较小时优先未近期参赛者；
- 国内冠军和杯赛冠军保留最低资格保障，不被轮换机制抹除；
- 所有平分使用 `clubId` 作为最终确定性排序键。

覆盖目标：3 年内至少 60%–70% 的顶级联赛球队获得洲际资格赛或正赛机会；5 年内绝大多数顶级联赛球队至少被洲际赛事或相关事实新闻触达一次。低级别球队主要通过国内杯赛、升级和球员转会进入洲际叙事，不直接随机获得正赛名额。

### 3.3 世界转会层：后台全量、玩家精选

转会系统拆为两个边界：

#### 玩家报价池

继续按照球员能力、位置、声望、合同和适应性筛选玩家可见报价。每国 3 家代表队只负责控制玩家当下的选择数量和阅读负担。

#### 世界转会市场

每个转会窗口让 240 队都具备成为转入方或转出方的资格。后台候选由以下事实驱动：

- 位置需求和阵容缺口；
- 联赛级别、工资预算和俱乐部发展周期；
- 升级、降级、换帅、伤病和洲际资格；
- 合同到期、核心球员离队和连续低出场；
- 球员能力、国别、语言和职业目标。

世界转会记录只保存必要摘要，例如来源俱乐部、目标俱乐部、窗口、位置/球员、状态、原因和关联事实。玩家可见的转会新闻按相关性筛选，不把 240 队的后台转会全部堆到当前页面。

### 3.4 新闻与传闻层：覆盖驱动但事实优先

可生成的俱乐部动态包括：

- 升级、降级、夺冠和杯赛爆冷；
- 获得或失去洲际资格；
- 洲际晋级、出局和重要对手变化；
- 关键位置缺口和引援目标；
- 球员合同到期、转会谈判和核心离队；
- 连续多个窗口无引援、换帅或球队重建。

动态相关性排序如下：

```text
相关性 = 与玩家当前俱乐部关系
       + 当前联赛关系
       + 国家队/队友关系
       + 洲际对手关系
       + 事实新鲜度
       - 最近重复出现次数
```

每个动态必须包含：

```text
clubId / relatedClubIds
window 或 occurredOn
category
summary
relatedFactId
relevance
```

同一俱乐部同类动态设置冷却期；重大新事实可以突破冷却期。前端提供按国家、联赛级别、洲际赛事和转会窗口筛选的“世界足坛”入口，并允许玩家查看俱乐部名称、所属国家、级别、近期排名和相关历史摘要。

## 4. 数据与模块边界

### 4.1 静态内容

沿用 `ClubProfile` 作为俱乐部静态资料来源，包括名称、国家、级别、地区、位置需求、青训周期和工资预算。不要为每一支球队复制一套独立模拟规则；实力和状态应由现有级别、内容字段与确定性赛季状态推导。

### 4.2 世界赛季状态

在现有 `WorldRegistry` 的紧凑摘要基础上扩展世界俱乐部状态，建议至少包含：

```text
clubId
country
tier
seasonId
finalRank / points
domesticHonours
continentalQualification / continentalResult
continentalAppearancesLast3
transferActivityLast2
lastNewsWindow
```

不保存非玩家俱乐部逐场比赛明细。滚动计数只保留进行资格轮换、重复控制和传闻排序所需的最近窗口数据。

### 4.3 模拟与应用层

- `packages/simulation`：国家联赛、洲际资格评分、背景赛季摘要、世界转会候选、传闻候选排序；不访问浏览器、存储或外部服务。
- `packages/application`：按月份/节点推进世界状态，协调赛季结算、转会窗口、动态生成和暂停恢复；不让 UI 直接修改比赛或资格规则。
- `apps/web`：展示玩家相关动态和可筛选的世界足坛摘要；俱乐部名称统一从内容目录解析，不在组件内维护数据副本。
- `packages/contracts`：保存可迁移的世界摘要、转会摘要和事实关联字段。

## 5. 数据流

```text
八国赛历与联赛结算
        ↓
每队赛季摘要 + 升降级
        ↓
洲际资格筛选 ───→ 洲际摘要
        ↓
球队状态与位置需求
        ↓
世界转会窗口 ───→ 转会事实
        ↓
全部事实统一进入动态候选池
        ↓
按玩家相关性、冷却期和阅读预算展示
```

世界层的背景计算可以完整覆盖 240 队，但玩家当前页面默认只显示最相关的 3–5 条动态；历史页面提供筛选和分页，不因扩大球队数量而增加默认阅读负担。

## 6. 存档与一致性

- 进行中的存档保存当前世界注册表、赛季摘要、资格状态、转会窗口状态、传闻游标和确定性随机状态；刷新后继续推进必须得到相同结果。
- 已结束存档不保存完整世界逐场数据，只保留与玩家履历、球队经历、转会、荣誉和回顾有关的摘要。
- 每条洲际、转会和传闻动态必须关联已经写入的事实；删除或迁移事实时不能留下无法解析的俱乐部 ID。
- 俱乐部从一个国家转移后，旧国家赛历、旧杯赛资格和旧新闻上下文必须在迁移点结束，不产生双重赛程。

## 7. 验收指标

### 硬性指标

- 每赛季国内联赛俱乐部覆盖率为 240/240；
- 所有动态引用的俱乐部 ID 都能在八国内容目录中解析；
- 同一赛季同一俱乐部不进入两个国家的国内联赛或国内杯；
- 相同存档、种子和输入重复运行，世界赛季、转会和动态顺序完全一致；
- 非玩家世界状态不产生逐场明细膨胀；
- 不允许无事实来源的新闻或传闻。

### 分布指标

- 3 年洲际机会覆盖率达到顶级联赛球队的 60%–70%；
- 5 年内绝大多数顶级联赛球队至少出现于一次洲际或世界动态；
- 同一球队在没有新事实时不连续占据同类动态；
- 强队仍可因成绩连续参赛，轮换不改变联赛层级单调性；
- 玩家默认页面的动态数量和阅读负担不随 240 队线性增长。

## 8. 实施顺序与边界

1. Task12 先完成八国独立国内赛历、双循环赛程和升降级链，作为世界生态的基础。
2. 后续单独建立“世界足球生态”实施任务，加入洲际资格与结果摘要、世界转会窗口和事实驱动新闻。
3. Task13 的跨国转会吸引力与适应期可以复用世界转会市场，但不应重复创建第二套转会候选系统。
4. 国家队亚洲杯、世界杯、友谊赛的完整赛事安排不属于本设计，仍按此前决定留待后续任务。
5. 第一阶段不模拟所有非玩家洲际逐场比赛，只模拟资格、赛果、排名、荣誉和可追溯动态；玩家俱乐部进入相关赛事后再展开详细体验。

## 9. 测试策略

- simulation 单测：国内覆盖、洲际资格、软轮换、平分确定性、转会候选、新闻冷却和事实关联；
- application 测试：赛季结算后世界状态写回、转会窗口推进、刷新/恢复一致性和玩家相关动态筛选；
- contracts 测试：世界状态、转会摘要、动态记录迁移与严格字段校验；
- web 测试：240 队名称解析、国家/级别筛选、默认动态阅读预算和相关动态展示；
- balance 测试：100/1,000 赛季统计国内覆盖率、洲际机会覆盖率、球队重复率、转会触达率、动态来源完整率和存档体积；
- E2E：玩家完成一个国内赛季、一个洲际资格赛季和一次转会窗口后，刷新仍能恢复正确的世界摘要和动态。
